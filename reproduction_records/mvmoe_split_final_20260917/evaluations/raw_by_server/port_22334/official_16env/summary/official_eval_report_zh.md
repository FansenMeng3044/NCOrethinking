## 评测口径

- 官方提交：`af29e5af0595f94f3ecc3bc46d72df1089a62682`
- 任务：6 个训练内（IID）环境和 10 个未训练 zero-shot OOD 环境，共 16 个环境
- 数据：每个环境 1,000 个官方实例
- 推理：greedy、POMO size = n、8-fold augmentation、seed = 2024
- 模型：POMO-MTL-Split 的最终 `epoch-5000.pt`
- 可行性：每个 `ok` 结果均在评测器中独立重放并验证全部适用约束和路线代价
- 正式推理耗时：n=50 为 111 秒，n=100 为 248 秒（不含数据传输和 smoke test）

这里的 Gap 使用官方代码同一套参考文件逐实例计算后取平均。只有成功数为
1,000/1,000 时，才把它称为完整测试集 Gap；存在无可行候选时，表中的 Gap 仅是
成功实例上的条件均值，不能当作该环境的官方完整 Gap。

## 结论

1. 两个模型在六个训练环境上都达到 100% 可行，说明最终 checkpoint、数据接口、
   B 约束解码和精确 Split 的基本评测链路是有效的。
2. OOD 失败高度集中在同时含回程取货（B）与硬时间窗（TW）的四个组合环境：
   VRPBTW、OVRPBTW、VRPBLTW 和 OVRPBLTW。其余六个 OOD 环境在两个规模上均为
   1,000/1,000 可行。
3. n=100 在上述四个环境上几乎完全失效，成功数只有 6、11、8 和 10；n=50
   也仅有 163、194、169 和 197。精确 Split 只能在已经生成的访问顺序上移动路线
   边界，无法重排客户；因此，当候选 giant tour 与 B+TW 的联合可行结构不兼容时，
   后端 Split 无法补救。这是当前结果最重要的结构性发现。
4. 即使在 100% 可行的训练环境上，时间窗任务的 Gap 也显著高于不含时间窗的任务：
   n=50 的 VRPTW/OVRPTW 为 29.291%/21.544%，n=100 为 41.128%/31.192%。这说明
   问题不仅是能否切出可行解，location-only 顺序对时间约束下的路线质量也明显不足。
5. n=50 与 n=100 是不同规模，不能把两者代价直接横向比较；但成功率和各自参考
   Gap 均表明规模增大后泛化难度显著上升。
